Reviewed October 4, 2026. This is an evidence inventory, not a submission or an award prediction. Apple's published [terms](https://developer.apple.com/swift-student-challenge/policy/) still describe the **2026** Challenge, whose February 28 deadline has passed; [2027 rules](https://developer.apple.com/swift-student-challenge/) have not been published on the pages checked. Reconcile every item when the next rules appear.

The current local submission ZIP, generated by `scripts/prepare-ssc-submission.sh`, was built twice from public app commit `a105c50` with identical SHA-256 `f870ca9659a8d471f68191d2d1cc2ca8596e9a158efac9867d83e9a9eaa94089` and size **12,188,958 bytes**. Archive integrity passed. It contains one `.swiftpm`, English-only strings/catalog, no research files, and no symbolic links. A clean extraction of this exact hash built with Xcode 26.6 for iOS Simulator. On an isolated iPhone SE Simulator, two fresh-install UI tests of this exact package passed with zero failures in 49.56 seconds of automated test time: first-launch photo picker opening/cancellation, then Practice selection → confirmation → final Review with a Practice label → save → History → saved detail → delete. The same clean-extracted app was installed on an isolated iPad mini (A17 Pro) Simulator: first-launch photo picker/cancel, Practice estimate and confirmation, final Review, save, and light/dark Home were exercised and visually checked without clipped controls on those screens. Separate English and Arabic maximum Dynamic Type tests on the preceding UI version passed; the current welcome mark was visually checked at maximum text in Urdu. Xcode reported non-blocking duplicate `Brand.xcassets` build-file warnings. Mac evidence does not establish physical-device behavior.

## What the current app can do

| Capability | Current behavior and limit |
| --- | --- |
| Start a meal | First launch asks the person to choose their own meal photo and opens Apple's native library picker; it no longer preselects a Practice meal. Home places Camera and Library above the large theme artwork, with a general Start action. The person can also type a description or select one of three optional Practice meals. A selected photo alone can advance to review. Camera capture and return have not been verified on physical hardware. |
| Inspect a photo offline | Uses Apple's local Vision classifier and a small bundled food catalog. It never uploads the image. Possible food matches start excluded, and a photo never sets portions or carbohydrate grams. Photo preparation now handles 2× and CIImage-backed camera input without retaining an unprepared full-size result; a synthetic large CIImage still had high peak decode memory. The current iOS 26.5 Simulator returned unrelated scene labels for three different meal images; the app shows inspection unavailable and no range in that case. Broad or reliable any-meal recognition is **not implemented**. |
| Recover from an unknown photo | Allows the person to name foods or enter a carbohydrate amount copied from packaging or another trusted source. The result identifies that input as user-entered. This is not nutrition validation. |
| Review an estimate | Shows included and excluded items, adjustable portion choices for local catalog examples, an illustrative range where supported, a source/review trail, and a final confirmation step. The local catalog is finite and its example ranges are not clinically validated. |
| Learn with Practice | Includes synthetic biryani, grain-bowl, and breakfast images with example review data. These values teach the controls; they are not measurements of those pictured servings. |
| Save and control history | Can save reviewed meal items, their sources and portions, the meal origin (Practice, description, or selected photo), reference-item choice, range, and date in protected local storage; shows saved reviews and offers deletion. Practice is labeled at final Review before Save and in history, where its ranges are explicitly examples. Older records with no saved origin are marked unknown; photo-only records receive a neutral title. It does not save meal photos. The exact `f870ca96` archive passed Practice save → History → detail → delete in a fresh-install Simulator test. |
| Work without an account | Meal review, reference content, assets, and storage are local. There is no required server, sign-in, judge tracking, or analytics in the candidate source. Actual offline airplane-mode use on a physical device is still unverified. |
| Present the Pixel Kitchen theme | Uses the selected circular pot emblem with star accents, warm adaptive colors, bundled Pixelify and Nunito fonts, food-ring loading art, and matching review cards. Compact welcome shows its photo promise and insulin boundary before scrolling; compact Home keeps Camera/Photos prominent and the settings control aligned in Arabic RTL. Light/dark English, Arabic, and Urdu iPhone SE screenshots were inspected, including the final free-circle welcome art. Full every-screen visual review remains open. |
| Support languages | The everyday source offers English plus 17 other language choices, with matching catalog keys. The photo-picker action now says Photos or a photo-specific equivalent across all 18 catalogs; compact Urdu, Japanese, Hindi, Bengali, and Tamil labels were visually checked. The new Meal source row has a translated short label in each non-English catalog. A static audit found 34 catalog keys whose values still equal English across all 17 non-English choices, including fixed numerals/brand text and 30 other phrases such as safety, privacy, photo-uncertainty, and VoiceOver copy. An older-record sentence is uncatalogued and falls back to English; the Privacy date stamp also uses a source string different from the catalog key. Native review is open; do not describe everyday localization as complete. The Challenge ZIP contains English only, matching the last published rules. |
| Accessibility | Source includes VoiceOver labels/identifiers, section-heading traits, and Reduce Motion handling. The welcome Photo action is pinned at maximum Dynamic Type; independent English and Arabic iPhone SE checks on `ef61aa5` confirmed it remains visible and tappable while safety copy scrolls. The final `cf59191` welcome art was visually checked at maximum text in Urdu with its Photo action visible. Exact-ZIP iPad mini light onboarding, picker, two-column meal entry, Practice estimate/Review, and light/dark Home were inspected with no clipping on those screens. Direct VoiceOver speech/swipe traversal, full iPad coverage, contrast, and runtime Reduce Motion checks remain incomplete. |

The candidate does **not** connect to Dexcom or Libre, compute insulin units, provide a correction or treatment recommendation, measure portions from an image, or reliably recognize arbitrary home-cooked, restaurant, mixed, and culturally varied meals. Those missing capabilities must not be implied by the demo. See [PLAN.md](PLAN.md) and the [competitive review](COMPETITIVE-REVIEW.md) for the product direction and RxFood comparison.
